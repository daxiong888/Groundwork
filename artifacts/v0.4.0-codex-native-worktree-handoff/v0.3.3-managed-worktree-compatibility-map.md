Decision Supported: Which v0.3.3 managed-worktree fields remain compatibility contract, which move to Codex-native evidence or availability markers, and which fixture rows must stay as compatibility coverage until native-alignment fixtures replace them.
Artifact Type: compatibility and migration map

Out of Scope: Removing or renaming adapter files, changing public skill surface, executing Codex App Handoff or Worktree operations, refreshing plugin cache, creating runtime evidence, release readiness, UAT readiness, commits, pushes, or PRs.
Evidence Level: Local source inspection and compatibility mapping only. No runtime, cache, release, marketplace, UAT, or handoff-trial readiness is claimed.
Safe to Share / Redaction Notes: Safe to share as a design artifact. It contains file paths and schema field names only; no secrets, credentials, private URLs, browser cookies, PII, logs, or production data.

## Canonical Decision

`codex_app_managed_worktree_thread` remains the legacy internal adapter name during v0.4.0.

Reason:

- `skills/dispatch/adapters/codex_app_managed_worktree_thread/RATIONALE.md` says the adapter belongs under `dispatch` as an internal adapter contract, not as a public skill.
- V040-001 is a compatibility slice, not a rename slice.
- Renaming the adapter before V040-007 would break existing prompt/scenario rows and make compatibility coverage harder to compare.
- Native-alignment packages may introduce new schema sections, but the legacy adapter directory should stay in place until eval migration proves equivalent safety coverage.

## Runtime Identity Mapping

| v0.3.3 identity field | Native target | Availability rule |
| --- | --- | --- |
| `runtime_identity.runtime_correlation_id` | Compatibility correlation evidence; optional `native_context.thread_ref.value` only if it is the visible native reference | If no visible Codex-native thread reference exists, keep as compatibility ID and set native thread availability to `unavailable_in_current_surface`. |
| `parent_thread_identifier` | `native_context.thread_ref` evidence note or parent reference | Use `availability: visible` only when observed from Codex-native Handoff or thread UI/API evidence. Otherwise use `unavailable_in_current_surface` or `redacted`. |
| `child_thread_identifier` | `native_context.thread_ref` for worktree child/associated thread | For Local to Worktree before Handoff, use `unavailable_before_handoff`. For Worktree to Local, use `visible` only when cited evidence exists. |
| `thread_identifier` | `native_context.thread_ref` | Same as above; no invented IDs. |
| `worktree_path` | `native_context.worktree_path` | Use `unavailable_before_handoff` before Codex creates/exposes the worktree, `visible` when path evidence exists, `unavailable_in_current_surface` when Codex surface hides it, or `redacted` when intentionally withheld. |
| `worktree_type: Codex-managed` | `runtime_evidence.evidence_owner` and `native_context.worktree_association` | Treat as a claim requiring runtime or user-supplied evidence. Documentation-only packages must mark it unverified or not applicable. |
| `branch`, `base_ref`, `base_commit`, `child_head_commit` | Native package `base` and closeout merge-source evidence | Keep when visible from git or package evidence. Missing branch state must remain an explicit blocker or human decision. |
| `initial_thread_title`, `current_thread_title` | Supplemental display evidence | Keep as display-only. Title mutation must not break identity and must not replace native thread refs. |
| `pendingWorktreeId` | Pending operation evidence only | Never count as child-thread evidence. Map to availability `unavailable_before_handoff` or a pending evidence note until a real thread/worktree reference is visible. |

## Fixture Migration Boundary

Compatibility fixtures to keep until V040-007 proves replacement coverage:

- `evals/prompts/dispatch-managed-worktree-lifecycle.csv`: all rows are compatibility coverage for v0.3.3 lifecycle, merge-back, dirty worktree, init preflight, closeout serialization, and backward compatibility.
- `evals/prompts/goal-mode-hardening.csv`: compatibility coverage for first-line `/goal`, placeholder rejection, runtime Goal Mode evidence, and title mutation correlation.
- `evals/prompts/serial-dispatch-barrier.csv`: compatibility and continuing safety coverage for dependency barriers and base-refresh release evidence.
- `evals/prompts/clean-review-fanout.csv`: continuing safety coverage for fresh-context review and self-review rejection.
- `evals/scenarios/managed-worktree-lifecycle.md`: compatibility scenario source until a native-alignment scenario exists.

New native-alignment fixtures to add in V040-007 or later:

- route fixtures for `local_direct` versus `worktree_isolated` using workspace state, stale base, conflict, serial dependency, and runtime-surface availability;
- Local to Worktree handoff fixture where `native_context.worktree_path.availability: unavailable_before_handoff`;
- Worktree to Local handoff fixture with visible native context, changed files, evidence, open risks, and stop condition;
- native closeout fixtures rejecting `merge_decision.recommendation: merge` when evidence, git boundary, review status, or merge source is missing;
- dispatch-native-alignment fixture proving package generation does not claim Codex App worktree creation, Handoff execution, archive, cleanup, runtime success, cache refresh, or release readiness;
- local-environment setup fixture where setup requirements are route/setup evidence, not Groundwork-executed worktree setup.

## Removal and Rename Guardrails

No v0.3.3 adapter or eval files should be removed or renamed in V040-001.

Future removal or rename is allowed only when all conditions are true:

- the replacement native-alignment contract has landed;
- V040-007 fixture coverage maps the same safety intent;
- CSV parse and relevant runtime/eval validation pass for the touched suite;
- legacy references in dispatch, handoff, verify, docs, and eval scenarios are either updated or intentionally marked compatibility-only;
- the change report states that local fixture checks are not real Codex App runtime evidence.

## Non-Readiness Boundary

This map is local documentation evidence only.

It does not claim:

- Codex App worktree creation;
- Codex App Handoff execution;
- runtime/cache/source equivalence;
- plugin cache refresh;
- marketplace install evidence;
- archive execution;
- branch deletion;
- release readiness;
- UAT readiness;
- real Local to Worktree or Worktree to Local handoff trial success.
