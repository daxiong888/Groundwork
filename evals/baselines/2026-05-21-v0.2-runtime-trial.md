## Drift And Fixes

- `rel-001` initially did not load `implement` even though it behaved correctly. The prompt was changed from “先确认 bug 再改” to “修一下这个问题：... 先确认 bug 再改” to match the natural trigger more closely without using explicit skill invocation.
- `rel-003` initially did not load `write-plan` even though it behaved correctly. The prompt now says the task is accepted, matching the skill boundary of accepted work before edits.
- `rel-005` initially relied on read-only sandbox to prevent artifact writes. The prompt now explicitly says to output the plan without editing files.
- `rel-006` initially described a missing-evidence scenario while the fixture had runnable failing tests. The prompt and expected behavior now test the failing-test readiness path.
- `rel-007` stopped loading `verify` after the no-tests fixture wording was corrected. The prompt now leads with “验证一下” and the UAT question to preserve natural `verify` triggering.
- The first exploratory runtime run read memory because the prompt did not forbid it. All reliability prompts now include “不要读 memory” and the final runs did not read memory.

## Runtime Noise

- Codex CLI emitted remote plugin catalog / featured plugin `403 Forbidden` warnings from `chatgpt.com`. The installed local plugin cache was still usable.
- Codex CLI emitted unrelated marketplace / manifest warnings from other local plugins.
- `rel-008` attempted browser inspection through Chrome DevTools MCP, but the browser profile was already running. The output correctly marked browser/runtime evidence as unavailable instead of claiming verified visual behavior.
- Some fixture runs printed parent-repo dirty worktree state because the fixture directories live inside the Groundwork repo. No trial prompt edited files.
