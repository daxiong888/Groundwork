## Watch Items For Runtime Testing

1. `to-prd` may over-trigger on prompts containing `PRD` when the user only wants a tiny rewrite. Fixture `to-prd-005` and scenario 7 cover this; runtime selection should be observed.
2. Risky write prompts such as `implement-005` and scenario 8 test embedded `gate`, not a standalone public skill. Runtime behavior should be judged by whether it requests explicit approval before push/deploy, not by exact first public skill alone.
3. Scenario 8 intentionally allows `verify` or `implement` depending on whether readiness evidence already exists. Runtime baseline should record the chosen path and whether `gate` blocks external writes.
4. `prototype` visual and interaction claims must stay `unverified` unless browser/runtime inspection is actually available.
5. `write-plan` and `implement` must not introduce exact paths, APIs, schemas, or commands before source inspection; runtime outputs should be checked for this drift.
