## Drift / Failures / Skill Updates Needed

- `verify` scope-first drift: several expected `verify` rows used helpful review or findings-first output but did not begin with exact `Verification Scope`. Update `skills/verify/SKILL.md` or its references so every `verify` branch emits the scope block first, including frontend contract review, UI tool routing, and subagent prompt preparation.
- QA-fix-QA drift: `gr-009` produced a generic process instead of a structured expected/actual/reproduction/severity/minimal diagnosis/fix plan/re-QA report. Tighten the QA-failure branch in `skills/verify/QA-FIX-QA.md` or the verify trigger path.
- Git-boundary eval harness drift: the default isolated empty workdir cannot prove repo dirty/staged state for `gr-008`. Future runtime harness should run git-boundary rows from the real repo root in read-only mode, or the CSV row should specify the fixture/context explicitly.
- Repo-specific git-boundary context drift: the supplemental `gr-008` prompt did not mention that `README.md` and `.agents/plugins/marketplace.json` are out of scope for v0.2.2, so the runtime treated them as potential intended files. The baseline report, not the runtime row, preserves the correct out-of-scope decision.
