## Risks

- `rel-002` and `rel-006` show natural-language runtime prompts can still bypass Groundwork skills even when the output behavior is mostly correct. This weakens repeatable report shape and acceptance evidence.
- `life-002` shows `handoff` frontmatter is still broad enough to activate for explanation-only prompts.
- `life-015` shows lifecycle ownership decisions about external issue truth may need stronger `triage` trigger language.
- `life-008` used memory-derived context in a fixture-less release-planning answer. The row passed its acceptance target, but future evals may need explicit "do not read memory" language when memory isolation matters.

## Suggested Fix Direction

1. Tighten `handoff` trigger boundaries so one-off explanations of the skill do not load the skill workflow.
2. Strengthen `verify` natural-language trigger coverage for "ready for frontend integration" phrasing.
3. Strengthen `triage` trigger coverage for lifecycle-state ownership decisions and external source-of-truth decisions.
4. Re-check `implement` routing for implementation conformance review prompts that start with `review 这次实现是否符合 TASK.md`.
