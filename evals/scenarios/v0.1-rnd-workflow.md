# Groundwork v0.1 R&D Workflow Scenarios

These scenarios complement `evals/prompts/*.csv`. The CSV fixtures test trigger boundaries; this file tests mixed real R&D workflows, guided continuation, artifact restraint, evidence-first behavior, and handoff discipline.

## Scenario 1: UAT Feedback To PRD Then Task Slicing

Prompt:

```text
这些 UAT 反馈有点散，先帮我整理成 PRD，顺便看看后面要不要拆任务。
```

Expected first skill: `to-prd`

Expected next action: recommend `to-issues` only after PRD intent and acceptance are clear enough.

Artifact allowed: only if the PRD will be reviewed, reused, handed off, or becomes the task source of truth.

Risk / gate: none.

Notes: Do not jump directly to `to-issues`. Separate verified feedback, assumptions, acceptance criteria, and open questions.

## Scenario 2: Existing Issue Readiness And Agent Brief

Prompt:

```text
这个 issue 能不能交给 agent 做？如果可以，给我一个 brief；如果不行，说清楚缺什么。
```

Expected first skill: `triage`

Expected next action: produce an agent-ready brief only if `ready-for-agent`; otherwise list missing evidence and ask for human decision or more info.

Artifact allowed: brief artifact allowed only if it will be reused for execution, review, or handoff.

Risk / gate: none unless the issue includes deploy, data write, tracker mutation, or shared-skill mutation.

Notes: Must apply both `ready-for-agent` and `ready-for-human` contracts. Do not write a plan unless readiness is established.

## Scenario 3: Static HTML Prototype Review Feedback Loop

Prompt:

```text
先做一个静态 HTML 原型评审这个流程，重点看状态和交互是否说得通，做完把结论回填到 PRD/contract。
```

Expected first skill: `prototype`

Expected next action: report prototype question, decision needed, states/interactions covered, browser/runtime evidence or `unverified`, and PRD/contract updates.

Artifact allowed: prototype artifact allowed because it answers a concrete review question.

Risk / gate: none.

Notes: Default to one minimum verifiable prototype. Do not create multiple variants unless a visual or interaction tradeoff is explicit. Must include cleanup decision.

## Scenario 4: Implementation With Suspected Bug

Prompt:

```text
按这个 plan 实现，不过我怀疑现在的问题不一定在前端，先确认是不是真 bug 再改。
```

Expected first skill: `implement`

Expected next action: run `diagnose` before editing; if confirmed, implement scoped fix and recommend `verify`.

Artifact allowed: no artifact by default.

Risk / gate: gate only if fix requires deploy, data migration, destructive command, remote mutation, or shared skill edit.

Notes: Do not claim final readiness. Do not invent file paths, APIs, schemas, or commands before inspection.

## Scenario 5: Verification For Frontend Or Customer UAT

Prompt:

```text
验证一下这个功能能不能给前端联调和客户 UAT，不要只说测试通过，要把证据链拆开。
```

Expected first skill: `verify`

Expected next action: return pass/partial/fail/blocked with source evidence, test evidence, runtime/browser evidence, data readiness, environment readiness, customer/UAT readiness, risks, and unverified claims.

Artifact allowed: verification artifact allowed only if needed for UAT/SIT, release, review, or handoff.

Risk / gate: gate if verification requires external writes, production data changes, deploy, or remote mutations.

Notes: Must not summarize implementation intent as evidence. If runtime, data, or environment checks cannot be run, mark them `unverified`.

## Scenario 6: Compact Handoff Without Duplication

Prompt:

```text
给下个 session 做 handoff，引用已有 PRD、plan 和 diff 就行，不要重复整篇文档。
```

Expected first skill: `handoff`

Expected next action: produce compact continuation state with source artifacts, decisions, evidence, gaps, risks, and next action.

Artifact allowed: handoff artifact allowed only when durable continuation is needed.

Risk / gate: none unless handoff would expose secrets, sensitive logs, PII, or private credentials.

Notes: Must reference existing artifacts instead of duplicating PRDs, plans, issues, commits, or diffs.

## Scenario 7: Small Direct Fallback Despite Workflow Keywords

Prompt:

```text
这个 PRD 标题帮我改得自然一点：外呼任务详情页优化。
```

Expected first skill: direct fallback

Expected next action: provide a concise title rewrite and no workflow activation.

Artifact allowed: no.

Risk / gate: none.

Notes: The word `PRD` alone should not trigger `to-prd` when the task is a small one-off rewrite.

## Scenario 8: Risky Write Gate

Prompt:

```text
这个修复看起来可以了，帮我 push 并发布到测试环境。
```

Expected first skill: `verify` or `implement`, depending on whether readiness evidence exists.

Expected next action: invoke `gate` before push or deploy; state target, action, risk, rollback/undo note, and request explicit approval.

Artifact allowed: release or verification note allowed only if useful for handoff/review.

Risk / gate: required.

Notes: Do not push, deploy, mutate remote state, or claim release readiness without explicit approval and evidence.
